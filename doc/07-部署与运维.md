# Anywayone Blog 部署与运维

## 1. 目标环境

本文档对应 Anywayone Blog 的首个生产环境：

- Oracle Cloud Ubuntu ARM64，2 核、12GB 内存、100GB 磁盘。
- `www.anywayone.com`：Next.js 展示端。
- `admin.anywayone.com`：React 管理端。
- `api.anywayone.com`：FastAPI。
- `anywayone.com`：永久跳转到 `www.anywayone.com`。
- Cloudflare：DNS，应用稳定后启用代理。
- PostgreSQL：安装在同一台宿主机，不进入 Docker Compose。
- GitHub Actions：检查、构建 ARM64 镜像并通过 SSH 自动发布。

生产拓扑：

```text
Internet
   |
Cloudflare
   |
Oracle Cloud :80/:443
   |
Caddy
   |-- www.anywayone.com   -> web:3000
   |-- admin.anywayone.com -> admin:8080
   `-- api.anywayone.com   -> backend:8000
                                  |
                                  `-> host PostgreSQL:5432
```

Oracle Cloud 不开放 `3000`、`8080`、`8000` 和 `5432`。容器服务只在 Docker 私网中可见。

## 2. 自动发布边界

Pull Request 触发 `.github/workflows/ci.yml`，只执行检查和构建，不接触生产 Secrets。

上游仓库 `main` 分支更新后，`.github/workflows/deploy.yml` 执行：

1. 运行 Web、Admin、Backend 和部署配置检查。
2. 构建 `linux/arm64` 镜像并推送到 GHCR。
3. 使用 Git commit SHA 生成不可变镜像标签。
4. 上传 Compose、Caddy 和部署脚本到服务器。
5. 执行 Alembic 迁移。
6. 更新容器并等待健康检查。
7. 检查三个公开 HTTPS 地址。
8. 失败时恢复上一个应用镜像标签。

数据库迁移不会自动降级。生产迁移必须保持向后兼容，涉及删除字段或破坏性修改时使用“先扩展、后迁移数据、最后收缩”的多版本流程。

## 3. DNS 和网络检查

首次部署期间保持 Cloudflare 记录为灰色云朵 `DNS only`：

| 类型 | 名称 | 目标 |
| --- | --- | --- |
| A | `@` | Oracle 服务器公网 IPv4 |
| CNAME | `www` | `anywayone.com` |
| CNAME | `admin` | `anywayone.com` |
| CNAME | `api` | `anywayone.com` |

Oracle Cloud 入站规则只需要：

| 来源 | 协议 | 端口 |
| --- | --- | --- |
| 家庭公网 IP `/32` | TCP | 22 |
| `0.0.0.0/0` | TCP | 80 |
| `0.0.0.0/0` | TCP | 443 |

确认解析：

```bash
dig +short anywayone.com
dig +short www.anywayone.com
dig +short admin.anywayone.com
dig +short api.anywayone.com
```

## 4. 安装 Docker

以下命令在 Oracle Ubuntu 服务器执行：

```bash
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
```

添加 Docker 官方软件源：

```bash
. /etc/os-release
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu ${VERSION_CODENAME} stable" | sudo tee /etc/apt/sources.list.d/docker.list >/dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
```

验证 ARM64 和 Compose：

```bash
uname -m
docker --version
docker compose version
sudo docker run --rm hello-world
```

`uname -m` 应返回 `aarch64`，Docker Compose 应显示版本信息（v2 或更新版本均可）。

如果 `apt` 提示锁被占用，先使用 `ps` 检查对应进程。正常运行的 `apt-daily` 或 `unattended-upgrades` 应等待完成；不要直接删除 `/var/lib/apt/` 或 `/var/lib/dpkg/` 下的锁文件。只有确认自动更新已长期卡死后，才通过 systemd 正常停止对应服务并运行 `sudo dpkg --configure -a`。

## 5. 创建部署用户

不要让 GitHub Actions 使用日常登录账号或个人 SSH 私钥。创建专用部署用户：

```bash
sudo adduser --disabled-password --gecos "" anywayone
sudo usermod -aG docker anywayone
sudo install -d -m 700 -o anywayone -g anywayone /home/anywayone/.ssh
sudo cp /home/ubuntu/.ssh/authorized_keys /home/anywayone/.ssh/authorized_keys
sudo chown anywayone:anywayone /home/anywayone/.ssh/authorized_keys
sudo chmod 600 /home/anywayone/.ssh/authorized_keys
sudo install -d -m 750 -o anywayone -g anywayone /opt/anywayone
```

如果当前 Ubuntu 用户名不是 `ubuntu`，将复制命令中的路径改为实际用户路径。Docker 组具有接近 root 的权限，因此该账号只用于部署。

另开一个本地终端验证后再关闭当前 SSH 会话：

```bash
ssh anywayone@服务器公网IP
docker version
```

## 6. 安装 PostgreSQL

在宿主机安装 PostgreSQL：

```bash
sudo apt install -y postgresql postgresql-contrib
sudo systemctl enable --now postgresql
sudo -u postgres createuser --pwprompt anywayone
sudo -u postgres createdb --owner=anywayone anywayone_blog
```

`createuser` 会交互式询问数据库密码。该密码随后写入服务器的 `backend.env`，不要放入仓库或 GitHub Secrets。

让 PostgreSQL 接受 Docker 私网连接：

```bash
sudo -u postgres psql -c "ALTER SYSTEM SET listen_addresses = '*';"
sudo -u postgres psql -tAc "SHOW hba_file;"
```

第二条命令会输出实际的 `pg_hba.conf` 路径。使用 `sudoedit` 打开该文件，并在末尾加入：

```text
host    anywayone_blog    anywayone    172.30.0.0/24    scram-sha-256
```

重启并检查：

```bash
sudo systemctl restart postgresql
sudo systemctl status postgresql --no-pager
sudo ss -lntp | grep 5432
```

PostgreSQL 会监听宿主机端口，但 Oracle Cloud 入站规则不得开放 `5432`。`pg_hba.conf` 只允许本项目固定 Docker 子网中的应用账号访问目标数据库。

## 7. 创建生产环境变量

先创建空文件并限制权限：

```bash
sudo install -m 600 -o anywayone -g anywayone /dev/null /opt/anywayone/.env
sudo install -m 600 -o anywayone -g anywayone /dev/null /opt/anywayone/backend.env
```

生成 Backend 密钥：

```bash
openssl rand -hex 32
```

编辑 `/opt/anywayone/.env`：

```dotenv
ACME_EMAIL=你的证书通知邮箱
IMAGE_TAG=latest
```

编辑 `/opt/anywayone/backend.env`：

```dotenv
APP_ENV=production
DATABASE_HOST=host.docker.internal
DATABASE_PORT=5432
DATABASE_NAME=anywayone_blog
DATABASE_USER=anywayone
DATABASE_PASSWORD=数据库用户密码
DATABASE_SSL_MODE=disable
DATABASE_POOL_SIZE=5
DATABASE_MAX_OVERFLOW=5
SECRET_KEY=openssl生成的随机字符串
ACCESS_TOKEN_EXPIRE_MINUTES=15
REFRESH_TOKEN_EXPIRE_DAYS=30
CORS_ORIGINS=https://www.anywayone.com,https://admin.anywayone.com
COOKIE_SECURE=true
```

同机 Docker 私网连接使用 `DATABASE_SSL_MODE=disable`。数据库端口不允许公网访问。

## 8. 配置专用 GitHub Actions 密钥

在本地电脑生成一把新的部署密钥，不要复用个人密钥：

```bash
ssh-keygen -t ed25519 -C "anywayone-github-actions" -f ~/.ssh/anywayone_github_actions
ssh-copy-id -i ~/.ssh/anywayone_github_actions.pub anywayone@服务器公网IP
```

确认专用密钥可以登录：

```bash
ssh -i ~/.ssh/anywayone_github_actions anywayone@服务器公网IP
```

在服务器查看 SSH 主机密钥指纹：

```bash
sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

在本地扫描主机密钥，并人工比对指纹：

```bash
ssh-keyscan -H -p 22 服务器公网IP
```

进入 GitHub 仓库：

`Settings → Environments → New environment → production`

在 `production` Environment 中配置：

| Secret | 内容 |
| --- | --- |
| `DEPLOY_HOST` | Oracle 服务器公网 IP |
| `DEPLOY_PORT` | `22` |
| `DEPLOY_USER` | `anywayone` |
| `DEPLOY_SSH_KEY` | `~/.ssh/anywayone_github_actions` 私钥全文 |
| `DEPLOY_KNOWN_HOSTS` | 已验证的 `ssh-keyscan -H` 完整输出 |

不要把数据库密码或 Backend `SECRET_KEY` 配置到 GitHub，它们只存在于服务器。

## 9. 首次构建与启用部署

为了防止服务器尚未准备完成时自动发布，部署 job 受仓库变量控制。变量不存在时，工作流只检查代码并构建镜像。

1. 将部署代码合并到 `main`，等待 `Deploy production` 工作流构建三个 GHCR 镜像。
2. 在 GitHub 个人或组织的 Packages 页面，将以下镜像设置为 Public：
   - `anywayone-web`
   - `anywayone-admin`
   - `anywayone-backend`
3. 进入 `Settings → Secrets and variables → Actions → Variables`。
4. 新增仓库变量 `PRODUCTION_ENABLED`，值为 `true`。
5. 在 Actions 页面手动重新运行 `Deploy production`，或向 `main` 合并下一次提交。

部署成功后检查：

```bash
cd /opt/anywayone
docker compose ps
docker compose logs --tail=100 caddy
docker compose logs --tail=100 backend
```

首次 Alembic 迁移完成后创建生产管理员：

```bash
cd /opt/anywayone
docker compose exec backend python -m app.cli create-admin
```

管理员密码只在服务器终端输入。

## 10. 启用 Cloudflare 代理

确认以下地址都能通过 HTTPS 访问：

- `https://www.anywayone.com`
- `https://admin.anywayone.com/login`
- `https://api.anywayone.com/health/ready`

然后将 Cloudflare DNS 记录切换为橙色云朵，并设置：

```text
SSL/TLS encryption mode: Full (strict)
```

不要使用 `Flexible`。

## 11. 常用运维命令

查看状态与日志：

```bash
cd /opt/anywayone
docker compose ps
docker compose logs --tail=200 backend
docker compose logs --tail=200 web
docker compose logs --tail=200 admin
docker compose logs --tail=200 caddy
```

手动执行迁移：

```bash
docker compose run --rm --no-deps backend alembic upgrade head
```

使用一个已存在的 Git commit 镜像标签手动回退应用：

```bash
cd /opt/anywayone
IMAGE_TAG=sha-完整Git提交哈希 docker compose up -d --remove-orphans --wait
```

该命令不会回退数据库。上线后还应补充 PostgreSQL 定时备份、OCI Object Storage 异地备份和监控告警。
