# Anywayone Blog UI 设计方案

> 文档版本：v1.0  
> 视觉方向：轻动漫编辑风  
> 适用范围：Web 展示端、Admin 管理端  
> 设计基线：2026-08-27

## 1. 设计定位

Anywayone 的视觉不是动漫社区，也不是套用角色插画的通用博客模板。个人 IP 只在品牌识别、登录、头像和空状态中承担情绪表达；文章、摄影与后台工作区保持安静、清晰和专业。

设计关键词：编辑感、留白、纸张、克制、个性、可读。

固定品牌文案：

- 品牌名：`Anywayone`
- 英文口号：`ANYWAY, BE YOUR ONE.`
- 中文标语：`不设限，做唯一的自己。`

## 2. 素材使用规范

### 2.1 素材映射

| 素材 | 文件 | 固定用途 | 禁止用法 |
| --- | --- | --- | --- |
| 全身 IP | `Material/original_reference.png` | 首页第一屏右侧主视觉 | 文章封面、摄影占位图、后台大面积背景 |
| 头像 | `Material/avatar.png` | 首页个人档案、联系页、后台账号头像 | 拉伸、非等比裁切、重复平铺 |
| 横版 Wordmark | `Material/logo-svg/Anywayone.svg` | 桌面导航与登录品牌区 | 缩小到无法辨认、改变字标比例 |
| `A.` Logo | `Material/logo-svg/logo.svg` | 移动端导航、后台侧栏、favicon | 与横版 Wordmark 同时重复展示 |
| 品牌规范图 | `Material/150216bc-2374-4225-9b7e-b0403ec6b280.png` | 设计对照，不直接进入产品页面 | 作为页面背景或内容插图 |

摄影样片统一放入 `Material/photography/`，接受 JPG、PNG、WebP。原型和视觉验收建议提供 6–10 张横竖混合的真实作品；没有真实作品时必须显示空状态，不用 IP 图或图库图冒充摄影作品。

### 2.2 角色构图

- 桌面首屏角色可占可视宽度的 40%–48%，落在右侧并允许衣摆轻微出界；面部、帽子和主要动作不得被导航或文字遮挡。
- 平板角色降低对比并后移，文字保持第一阅读层级。
- 手机采用下半屏构图，保留面部与品牌特征；不得把角色缩成无意义的小贴纸。
- 角色周围不增加渐变球、光斑或复杂场景。可使用橙色圆点、斜切线和极少量漫画标注建立品牌语气。

## 3. Design Tokens

### 3.1 颜色

| Token | 值 | 用途 |
| --- | --- | --- |
| `color.ink` | `#1A1A1A` | 主文本、主按钮、导航 |
| `color.paper` | `#F0EFEA` | 展示端主背景 |
| `color.muted` | `#8D8D8D` | 次要文本、占位信息 |
| `color.textSecondary` | `#6B6964` | 暖白底上的小号辅助文字，满足 AA |
| `color.brand` | `#E6A01F` | 品牌圆点、焦点、进度、活动指示 |
| `color.line` | `#D5D2C8` | 细边框、分隔线 |
| `color.surface` | `#F8F7F3` | 输入框与必要工作面 |
| `color.photoCanvas` | `#11120F` | 摄影详情背景 |
| `color.photoText` | `#F5F2EA` | 摄影详情正文 |
| `color.photoAccent` | `#F0A62A` | 暗色画布焦点和进度 |
| `color.danger` | `#B42318` | 错误与危险操作 |

橙色不能单独承担状态含义，必须与文字、图标或形状同时出现。常规主按钮使用黑底白字；亮橙底仅用于小面积标记，不使用橙底白字正文。官方辅助灰 `#8D8D8D` 只用于非关键装饰、禁用轮廓或满足大字号条件的内容；暖白底上的 13–16px 辅助文字使用 `#6B6964`。

### 3.2 字体与字号

- UI、导航、标题：`Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。
- 文章正文：`"Source Han Serif SC", "Noto Serif CJK SC", "Songti SC", serif`。
- 代码：`"JetBrains Mono", "SFMono-Regular", Consolas, monospace`。
- Hero 标语：桌面 88px、平板 64px、手机 44px；不使用 `vw` 连续缩放，字距为 0。
- 页面标题：桌面 44px、移动端 32px；区块标题 24px；卡片/面板标题 16–18px。
- UI 正文 16px；辅助信息 13–14px。文章正文桌面 18px、移动端 17px，行高约 1.85。
- 字重仅使用 400、500、600；大标题避免依赖超粗字重制造冲击。

### 3.3 几何与空间

- 间距基数为 4px，常用值：4、8、12、16、24、32、48、64、80。
- 最大内容宽度：展示列表 1200px，文章正文约 720px，后台工作区随侧栏自适应。
- 圆角：输入与小控件 4px，按钮和卡片不超过 8px；摄影画布不使用装饰圆角。
- 边框：默认 1px 实线；编辑分组可用 1px 虚线。阴影仅用于浮层和拖拽态。
- 禁止卡片嵌套卡片。页面区块使用留白和分隔线组织，卡片只用于重复项目、模态框或明确边界的工具。

### 3.4 图标与图形语言

- 功能图标统一使用 Lucide，默认 18px；纯图标按钮至少提供 40×40px 可点击区域和可访问名称。
- 返回、关闭、排序、复制、上传等使用通用图标，不绘制自定义 SVG。
- 橙色圆点用于品牌落款或当前项，斜切线用于区块编号，漫画标注最多一处且不承载关键内容。

## 4. 展示端页面规格

### 4.1 固定导航

- 桌面高度 80px，左侧横版 Wordmark，右侧依次为首页、文章、摄影、关于我。
- 移动端高度 64px，左侧 `A.` Logo，右侧菜单按钮；抽屉打开后锁定背景滚动并把焦点移入菜单。
- 导航背景为有轻微透明度的暖白，但文字必须始终清晰；摄影详情导航切换为炭黑体系。
- 当前项同时使用文字状态和橙色短线/圆点，不只改变颜色。

### 4.2 首页第一屏

- 首屏高度 `100svh`，内容避开固定导航和设备安全区域。
- 左侧依次为英文口号、中文标语和“了解更多”；右侧为全身 IP。
- 中文标语可分为 2–3 行，但不得与角色脸部重叠。英文口号是辅助层级，不与主标语争夺注意力。
- “了解更多”使用黑底白字并带向下箭头；悬停、焦点和按下均有明确反馈。

### 4.3 首页翻屏交互

1. 用户点击“了解更多”，记录触发元素。
2. 内容壳在 500ms 内向上移动，桌面只保留首屏底部 80px，移动端保留 64px；固定导航不移动。
3. 第二屏从标题开始可滚动，默认选中“关于我”。
4. “关于我 / 站点日志”使用语义化标签页，方向键可切换，选中态为黑色文本加橙色指示。
5. 用户点击关闭或按 Esc，页面恢复首屏、滚动位置复位、焦点回到“了解更多”。

`prefers-reduced-motion: reduce` 时取消平移动画，直接切换状态；内容和焦点行为保持一致。

### 4.4 首页第二屏

“关于我”建议采用不嵌套的编辑式网格：

- 个人简介为主区域，头像作为唯一角色素材。
- 属性、职业、位置、装备使用紧凑信息行。
- 标签使用短文本和边框，不使用彩色胶囊墙。
- 人格模块可使用简洁坐标或字母值；跑步模块只展示真实已接入数据。

“站点日志”包含站点状态、客户端环境、文章/摄影统计、访问统计、趋势和站点历史。所有统计必须标明范围或单位；无数据统一显示 `—` 或“暂未记录”，图表不绘制伪造趋势。

第二屏之后直接进入页脚，不追加文章、摄影、推荐或营销区块。

### 4.5 文章列表与详情

- 列表使用分隔线式编辑布局，不用大面积卡片。标题、摘要、日期、分类与标签形成稳定扫描顺序。
- 长标题允许自然换行，不能挤压日期；移动端元信息移到标题下方。
- 详情正文约 720px；桌面目录位于正文右侧，移动端为正文前可展开目录。
- 顶部橙色细线表示阅读进度，同时为进度条提供可访问名称。
- 代码块使用深色背景、语言名称和 Lucide 复制按钮；长代码横向滚动，不撑破页面。
- 宽表格包裹在局部横向滚动容器中。图片大图查看完整支持关闭、键盘、焦点恢复。

### 4.6 摄影列表与详情

- 列表使用稳定的编辑式网格：桌面 3 列、平板 2 列、手机 1 列；通过明确 `aspect-ratio` 兼容横图和竖图。
- 不使用会造成布局跳动的动态瀑布流。每项只展示真实封面、标题及已配置的时间/地点/数量。
- 详情进入 `#11120F` 沉浸画布，正文为 `#F5F2EA`，操作焦点为 `#F0A62A`。
- 大图按摄影集顺序浏览，支持左右键、Esc、触控滑动；只预加载相邻一张。
- 关闭后恢复列表滚动位置并将焦点返回原缩略图。
- 无作品时用文字空状态和返回动作，不使用插画或占位摄影图。

### 4.7 联系页 `/about`

- 页面只展示头像、简短联系说明与已配置的邮箱、GitHub、微信等渠道。
- 未配置渠道整行隐藏，不显示禁用按钮或虚构账号。
- 复制账号后使用非阻塞反馈；外链明确目标并满足键盘访问。
- 不重复首页个人档案、装备、人格、跑步和站点数据。

## 5. 管理端规范

### 5.1 整体风格

- 采用克制的 Ant Design 工作台结构：白灰工作面、细边框、紧凑信息密度。
- 主操作黑底白字，当前导航使用橙色左侧短条加文字状态。
- IP 角色只用于登录、账号头像和空状态，不进入数据表、编辑表单背景或统计图。
- 桌面使用侧栏 + 顶栏 + 工作区；窄屏侧栏进入抽屉，编辑器主轴优先。

### 5.2 文章编辑器

- 顶部固定操作区包括返回、内容状态、保存状态、预览、发布/更新和更多菜单。
- 中央为标题、图标工具栏和 Markdown 编辑区；写作、分栏、预览采用分段控件。
- 右侧设置按发布、组织、展示、链接与 SEO 分组。窄屏下改为可关闭抽屉，不与编辑区并排挤压。
- 自动保存状态必须区分“保存中”“已保存”“仅本地保存”“冲突”和“失败”。
- 工具栏在 360px 下允许水平滚动或收纳低频项，但标题、保存和发布不能重叠。

### 5.3 摄影集编辑器

- 顶部提供批量选图/上传、预览、保存和发布；照片使用固定比例缩略图网格。
- 拖拽时显示明确插入位置与原位置；完成后通过非阻塞反馈告知新顺序。
- 每张照片提供可访问的“前移/后移”按钮，键盘排序与拖拽结果一致。
- 横竖图片使用 `object-fit: cover` 生成缩略图，编辑详情可查看完整比例。
- 窄屏网格降为单列或双列，图片标题、替代文本和排序控制不得覆盖缩略图。

## 6. 响应式规则

| 视口 | 关键规则 |
| --- | --- |
| ≥ 1200px | 1200px 内容宽度；Hero 左右构图；桌面目录；后台侧栏与设置栏同时可见 |
| 768–1199px | Hero 字号 64px；角色后移；摄影 2 列；后台设置栏可收起 |
| 390–767px | 导航 64px；Hero 字号 44px；角色进入下半屏；所有内容单轴排列 |
| 320–389px | 保持 44px Hero 字号并主动换行；工具栏收纳；最小触控目标约 44px |

- 不使用随视口连续变化的字号。
- 使用 `minmax()`、`aspect-ratio`、稳定网格轨道和明确的最小/最大尺寸防止布局位移。
- 支持 360px 页面无横向溢出；设备安全区域通过 `env(safe-area-inset-*)` 处理。

## 7. 动效与反馈

| 场景 | 时长 | 方式 |
| --- | --- | --- |
| 按钮/导航状态 | 160ms | 颜色、背景或小范围位移 |
| 标签内容切换 | 200ms | 轻微淡入，不改变容器高度策略 |
| 抽屉/设置栏 | 240ms | 位移 + 遮罩 |
| 首页翻屏 | 500ms | 单一缓动位移 |
| 大图切换 | 240–320ms | 内容位移或交叉切换 |

- 不使用循环漂浮、自动轮播、雨效、视差或音乐播放器。
- 保存、复制、上传和排序结果使用文本/图标反馈；失败消息说明原因和下一步。
- 骨架屏只在预期等待超过 300ms 时使用，并保持最终布局尺寸。

## 8. 可访问性与内容规则

- 文字、导航、按钮和摄影暗色页满足 WCAG 2.2 AA；正文对比度至少 4.5:1。
- 键盘可完成导航、翻屏、标签切换、编辑器操作、摄影排序和大图浏览。
- 焦点轮廓清晰，暖白主题使用橙色外圈与深色内边，暗色画布使用亮橙轮廓。
- 图片必须有符合内容目的的替代文本；纯装饰圆点和斜线隐藏于辅助技术。
- 空数据不填充示例数字或个人资料。管理端可用字段说明指导配置，展示端只显示 `—` 或空状态。
- 所有状态除颜色外至少再使用文字、图标或形状一种表达方式。

## 9. 验收清单

### 9.1 视觉与布局

- [ ] 在 1440×900、768×1024、390×844 和 360px 宽度检查导航、文字换行、角色裁切与页脚。
- [ ] Hero 字号严格使用 88/64/44px 三档，字距为 0。
- [ ] 页面不存在卡片嵌套、装饰渐变球、无意义大圆角或橙底白字正文。
- [ ] 文章长标题、宽表格、长代码均不造成页面级横向滚动。
- [ ] 摄影横竖图在列表和大图中保持稳定比例。

### 9.2 交互

- [ ] 首页展开、标签切换、关闭恢复、滚动位置和焦点返回正确。
- [ ] `prefers-reduced-motion` 下不执行大幅动画，功能不缺失。
- [ ] 摄影大图支持按钮、键盘、触控和焦点恢复。
- [ ] 后台摄影排序同时支持拖拽和键盘，结果一致且有反馈。
- [ ] 文章编辑器工具栏、设置区在桌面和窄屏不重叠。

### 9.3 数据与素材

- [ ] 首页个人资料、站点统计和联系页只展示真实配置数据。
- [ ] 无摄影样片时显示空状态；加入 6–10 张真实作品后重新检查比例、暗色画布和移动端加载节奏。
- [ ] 全身图、头像、Wordmark 和 `A.` Logo 使用场景符合素材映射。
- [ ] 所有图片声明尺寸、响应式派生图策略和替代文本。

### 9.4 质量

- [ ] 导航、主按钮、正文、辅助文字和暗色摄影页通过 WCAG 2.2 AA 对比度检查。
- [ ] 360px 下没有文字与按钮重叠、焦点不可见或不可操作控件。
- [ ] 生产页面达到 PRD 中的 Core Web Vitals 目标。
- [ ] 原型使用真实摄影样片完成最终视觉复核；没有样片时该项保持未通过。
